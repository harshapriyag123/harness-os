The invariant

Ambiguous execution state must not become a blind retry.

H-005: If an irreversible external operation returns an ambiguous execution state, it must not be blindly repeated without state verification or an idempotent operation identity.

Candidate repair

Give the operation an identity, then verify state after an ambiguous timeout.

operation_id = create_idempotency_key(order_id)
try:
    return refund.create(amount=249, idempotency_key=operation_id)
except TimeoutError:
    status = refund.lookup(operation_id)
    if status.completed:
        return status
    if status.not_found:
        return refund.create(amount=249, idempotency_key=operation_id)
    raise RequiresHumanReview()

Harness OS does not call this universally safe. The strongest allowed release language is ALLOW_FOR_TESTED_CONDITION, and only after an exact replay produces real evidence.

Why we built it

Agent reliability needs failure testing, evidence, and a human brake.

Traditional tests ask whether software returns the expected output. Autonomous agents also need tests for what happens when the outside world becomes ambiguous: a tool succeeds but times out, a retry duplicates an irreversible effect, or a proposed repair is about to mutate a real repository. Harness OS organizes that lifecycle as DISCOVER → MODEL → ATTACK → OBSERVE → PROVE → REPAIR → VERIFY → REQUEST HUMAN APPROVAL → ACT → RE-ATTACK → SAFETY CASE.

Harness OS · “CI proves your code works. Harness OS proves your agent can be trusted to act when the real world behaves unexpectedly.”
