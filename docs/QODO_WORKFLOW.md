# Qodo Workflow

Use Qodo from the first substantive change.

Recommended PR sequence:

1. `feat/harness-graph`
2. `feat/chaos-mcp`
3. `feat/trueforge-orchestration`
4. `feat/evidence-verifier`
5. `feat/approval-remediation`
6. `feat/flight-recorder-ui`
7. `feat/safety-case`

For each PR: describe **what**, **why**, architecture impact, test plan and screenshots where relevant. Resolve valid High-severity Qodo findings. If a finding is intentionally dismissed, explain why in the thread. Trigger follow-up review and merge only after it is recorded. Put at least one representative public merged PR in the README `Qodo Code Review Evidence` section.
